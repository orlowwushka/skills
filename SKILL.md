# Лонгрид-репорт в стиле Typeform

Скилл про **ремесло текста и структуры**, не про конкретную базу Marquiz. Референс жанра: [Typeform AI Report 2026](https://www.typeform.com/AI-data-report-2026).

**Полный разбор приёмов (обязательно при первом использовании в сессии):** [reference.md](reference.md).

---

## Когда применять

- Нужно **написать** или **отредактировать** лонгрид/отчёт уровня Typeform.
- Пользователь просит структуру, TOV, pull-quotes, key takeaways «как в их репорте».
- Есть цифры (опрос, исследование, CSV) — их подаём по правилам скилла; **цифры не выдумывать**.

**Не подменяет:** короткий лендинг (`dkcp-landing-writer`), рекламные креативы (`dkcp-ads-creative-writer`).  
**Данные Marquiz top-5000** — опциональный источник, см. конец файла; правило `.cursor/rules/top5000-quizzes.mdc` только если пользователь явно опирается на top-5000.

---

## Что это за жанр (одной фразой)

**Продуктовый data report:** индустриальный отчёт + журналистский лонгрид + скролл-лендинг + thought leadership. Не white paper и не SEO-статья из H2-подзаголовков.

## Порядок работы агента

### 1. Бриф (коротко, если не задан)

| Поле | Зачем |
|------|--------|
| Тема + год в заголовке | актуальность («2026: …») |
| Аудитория | тон и страхи глав |
| Источник данных | опрос n=…, отчёт, CSV — **откуда цифры** |
| Язык, «вы» / «ты» | единообразие |
| Бренд и один CTA | в конце, не в takeaways |
| Формат | markdown в `workspace/users/{email}/drafts/` по умолчанию |

### 2. Спроектировать три оси (главы)

**Запрещено:** одна тема на весь лонгрид.

**Обязательно:** три главы = три **разных вопроса или страха** читателя при одной большой теме.

Шаблон (адаптируй под тему):

```text
Глава 1 — норма / масштаб:     «что уже происходит у всех»
Глава 2 — напряжение / миф:    «что кажется страшным или спорным»
Глава 3 — действие / будущее:  «что делать и что остаётся за человеком»
```

Для каждой оси зафиксируй: **вопрос читателя**, **эмоциональную дугу**, **1 mega-stat + 1 контраст + 1 парадокс** (из данных, не из головы).

Примеры осей (Typeform): adoption → trust → job security.  
Примеры осей (другая тема): оффер → длина воронки → форма и результат.

### 3. Написать каждую главу по beat sheet

Строго следовать блокам **A→O** в [reference.md §3](reference.md). Соотношение: **~40% цифры / 35% интерпретация / 25% голоса**.

Минимум на главу:

1. **Pull-quote** — 8–14 слов, эмоция или парадокс (курсив/крупно).
2. **Opening** — контекст + первая цифра + контрастная цифра (2–4 предложения).
3. **Hero stats** — одна цифра на «экран», с человеческой подписью.
4. **Распределение или второй срез** — частота ≠ ценность, если уместно.
5. **Интерпретация** — «Данные однозначны…» / «Не X, а Y» (см. [reference.md §4–5](reference.md)).
6. **Культурный слой** — 3–5 однострочных якорей года/рынка, затем pivot к данным ([reference.md §7](reference.md)).
7. **Take carousel** — 4–6 блоков с лейблом CAPS (`MARKETER TAKE`, `CONSUMER TAKE` или свой, напр. `VOICE TAKE`).
8. **Bridge** — риторический вопрос в следующую главу.
9. **Key takeaways** — **ровно 3** буллета, императив на «вы»/«you».

**Переходы:** rhetorical Q, *But there's a crucial nuance*, *Instead,* *Luckily,* — [reference.md §3](reference.md).

### 4. Собрать документ (макро)

```text
Hero          — название + n выборки + дата
TOC           — 3 главы + Appendix (якоря)
Глава 1–3     — полный текст по beat sheet
Conclusion    — синтез БЕЗ новых цифр; «Мы верим…»; миссия бренда
Appendix      — кто опрошен / как считали / bonus stats
Brand + CTA   — один основной CTA; proof «этот отчёт сделан с помощью [продукт]»
```

**Story spine** (сквозной сюжет): универсальность → nuance → (опционально двойная перспектива) → снятие катастрофы → человек/практика → бренд как проводник — [reference.md §2](reference.md).

### 5. TOV при написании

| Делать | Не делать |
|--------|-----------|
| Уверенно, эмпатично к перегруженному специалисту | Хайп, морализаторство, вина читателя |
| Смягчители: *почти*, *более трети*, *лишь* | Академический пассив, канцелярит |
| «вы» в takeaways; «мы» в методологии | >3 takeaways; 10 CTA |
| Короткие фразы после цифр | >3 цифр подряд без прозы |
| Цитаты: не только позитив, с конкретикой | Фейковые цитаты |
| **Журналистская проза** — абзацы, риторические вопросы | **Таблицы в главах**, стены буллетов |
| Язык аудитории ниши (заявки, ЖК, подборка) | Имена полей CSV, `offer_pattern`, SMB, CR в теле |
| Mega-стат отдельной строкой + короткая подпись | «Тактика 1 / KPI / классификация» в заголовках |

Формулы и длина предложений — [reference.md §4](reference.md).

### 6. Data storytelling (если есть цифры)

1. Mega-stat → 2. Contrast pair → 3. Distribution → 4. Paradox (две аудитории / два среза) → 5. Footnote при необходимости.

После каждой цифры — **1–2 предложения**, что это значит в ежедневной работе читателя. Медиана устойчивее среднего при выбросах — оговорить в appendix.

### 7. Самопроверка перед отдачей

Чеклист — [reference.md §12](reference.md). Критично:

- [ ] 3 главы, у каждой pull-quote → stats → voice → 3 takeaways
- [ ] ≥1 парадокс или контраст на главу
- [ ] Conclusion без новых данных
- [ ] Appendix с n и методологией
- [ ] Один CTA

### 8. Итерация (рекомендуется)

1. **Черновик** — все три главы по beat sheet, не полировать стиль.
2. **Сжатие** — убрать воду, wall of stats, дубли между главами.
3. **TOV** — при запросе на бренд Marquiz: `brand-marketing` (Папа Бренда), не смешать с ДКЦП как заменой жанра.

Только если пользователь просит отчёт **по корпусу квизов**:
